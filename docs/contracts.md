# Evaluation kit contracts

These interfaces define the integration boundary of the shared evaluation kit.
The tree supplies the references and Gate P, the compiled `ammfast` replica,
replica/HA/engine banks under `baselines/`, the paired `score.py` scorer, and
the pinned, cached `setup_fast.sh` installer. See [ammfast.md](ammfast.md),
[replica-banks.md](replica-banks.md), [score.md](score.md), and [setup.md](setup.md)
for implementation details and recorded validation limits.

## Replica API

```python
ammfast.run(seed, policy, head_params=None) -> {"seed": int, "edge": float}
ammfast.run_batch(seeds, policy, head_params=None) -> list[dict]
```

`seed` is an integer replica seed. Policy IDs are exactly `qt1-ref`, `TwoComp`,
and `COMBO`. Unknown IDs must raise `ValueError`, not select a default policy.
`run` completes one replica2 simulation in one call and returns a finite,
unrounded edge. `run_batch` returns the same rows as calling `run` for each seed,
in input order, retaining duplicates; an empty seed list returns `[]`.
Neither function mutates caller inputs or retains policy state between runs.

`head_params=None` selects the unmodified policy. The residual-head hook belongs
to COMBO; its parameter shape and interpretation must be documented by the
implementation before non-None parameters are accepted. Unsupported head inputs
must raise an error rather than being silently ignored. This item does not choose
or train parameters. Public IDs map to the archived Numba IDs `qmref`, `twocomp`,
and `combo`, respectively; the archived kernel itself is not this public API.

Replica parity acceptance is per-seed absolute edge error <= `1e-9` against
CPython replica2, for all three policies on seeds `10000..10063` and
`64000..64063`. Report warm and cold timings separately and runs/second/core;
Gate P alone does not establish Numba parity.

Committed replica evidence in `baselines/replica/validation.json` includes
`gates384` (384 records) and `spots576` (576 records). Both arrays contain
`{policy, seed, cpython_edge, ammfast_edge, abs_error}` with unrounded values.
The former covers the parity seeds above; the latter covers the first 64 seeds
of each of the nine replica banks. See [replica-banks.md](replica-banks.md)
for bindings, timings, and the offline evidence validator.

## Bank JSON

A bank is a JSON object whose **first field is `_credit`**, followed by:

```text
_credit: attribution including Taylor, solved-policy research and full commit
backend: "replica" | "engine"
policy: "qt1-ref" | "TwoComp" | "COMBO" | "HA" | "qt1"
provenance: object
rows: [{"seed": integer, "edge": fixed-six-decimal string, ...}]
```

Replica policies are `qt1-ref`, `TwoComp`, `COMBO`, and `HA`. Engine policy `qt1`
names the pinned Solidity reference. `edge` is a finite decimal string matching
`^-?[0-9]+\.[0-9]{6}$`, produced with `format(edge, ".6f")`. Round only at bank
serialization; use unrounded floats in replica API results. Banks store rows in
ascending seed order, with unique seeds. A scorer must pair by seed and reject
missing, duplicate, incompatible-backend, or non-finite rows.

`provenance` must identify source commits and SHA256 digests, generation command,
backend/runtime versions, seed range, rounding, and validation evidence. Engine
provenance additionally identifies the release wheel and its SHA256, contract
SHA256, configuration construction, and worker count. No guessed values or
claims of unperformed checks belong in provenance.

Every engine row additionally has `after_swap_peak_gas: int` (nonnegative).
Engine seeds are restricted to the inclusive range `9700000..9700511`, for
screening only. Use the release wheel and
`amm_sim_rs.run_batch(X, VanillaStrategy, configs, 8)`, with configs built as in
`MatchRunner._build_configs`. The qt1 contract SHA256 must be
`c68887cff61180e12ba2b1ceb333edf76a830f91f63b5d775a8806fb9ec08aca`.

Committed replica banks cover `60000..61023`, `64000..65023`, and `10000..12047`
for each of the three policies. Spot-check 64 seeds per bank against CPython.
HA rows for `10000..12047` come from Taylor's `calib_out_2048.json` and retain
that provenance, rather than claiming to have been generated by ammfast.

## Paired scorer boundary

The implemented scorer consumes replica or engine rows paired against a compatible
bank, in rounds of 128 seeds, and prints `{n, mean_diff, se, worst5}` each round.
Diff means candidate edge minus baseline edge; `se` is the sample standard
error of those paired differences. Define and document `worst5` as the five
lowest paired differences with their seeds. Reject mixed backends. Stop early
when `mean_diff + 3 * se < 0`; optional above-bar stopping uses
`mean_diff - 3 * se > bar`. Define behavior for a final partial round and fewer
than two observations in the scorer implementation. Screening engine seeds
must never be represented as an independent final evaluation.
