# Replica banks

Per-seed baseline edges for `qt1-ref`, `TwoComp` and `COMBO` on Taylor (gtmcknight)'s replica,
generated by [ammfast](ammfast.md) after it passed the CPython parity gate.

## Files

| Path | Content |
|---|---|
| `baselines/replica/{policy}-60000-61023.json` | 1024 rows per policy |
| `baselines/replica/{policy}-64000-65023.json` | 1024 rows per policy |
| `baselines/replica/{policy}-10000-12047.json` | 2048 rows per policy |
| `baselines/replica/validation.json` | gate, spot checks, bindings, timings, coverage |
| `baselines/replica/generate.py` | resumable benchmark → gate → banks → spot → write |
| `baselines/replica/validate.py` | offline, standard-library check of all of the above |

Nine banks, 12288 rows. Each bank follows the contract: `_credit` first, then `backend`
(`"replica"`), `policy`, `provenance`, `rows`; rows are `{"seed": int, "edge": "ddd.dddddd"}` in
ascending seed order. Edges are unrounded in memory and in checkpoints and are formatted with
`format(edge, ".6f")` only when the bank is written. `provenance` records Taylor's commit, the
URL and SHA256 of every reference original, the ammfast source digests, the runtime versions, the
generation command, the seed range, the rounding rule and that bank's gate and spot-check results.

HA rows for `10000..12047` are a different bank (`baselines/ha/`), imported from Taylor's
calibration file and not produced here.

## Commands

```sh
bash setup_fast.sh --platform linux-x86_64 --replica-only && . scratch/env.sh
python -B baselines/replica/generate.py --stage all --workers 4 --budget 420   # exit 75 = run it again
python3 -B baselines/replica/validate.py                 # standard library only
python -B baselines/replica/validate.py --recompute 8    # also re-runs 8 seeds per bank with ammfast
python -B -m unittest discover -s tests -p test_replica_banks.py -v
python -B score.py --baseline baselines/replica/qt1-ref-60000-61023.json --replica --policy COMBO
```

`generate.py` checks its time box after every finished CPython run and every finished 128-seed
chunk and stops with exit code 75 when `--budget` seconds (default 420, maximum 450) are used; the
same command continues from the checkpoints. The benchmark (about 60 s, once per binding) and the
384 gate runs of ammfast (about 5 s) are not interruptible, so keep the command cap at 470 s. `--stage bench|gate|banks|spot|write|status` runs up to that stage. It uses no engine
seeds.

Stages, in order:

1. **bench** (first, once per binding): CPython seconds per run, cold and warm fresh-process first
   runs and single-worker `run_batch` rate for each policy, then a plan (runs, estimated seconds,
   128-seed chunks, worker count).
2. **gate**: 384 pairs, `ammfast.run` (one call per run) against CPython `replica2.run` with a
   fresh policy object per run, absolute error ≤ `1e-9` on unrounded edges. No bank is generated
   unless it passes.
3. **banks**: `ammfast.run_batch` in 128-seed chunks on spawned workers; each finished chunk is
   appended and fsynced.
4. **spot**: the first 64 seeds of each of the nine banks against CPython, 576 pairs. The 384 that
   coincide with gate pairs reuse the gate's CPython rows; 192 (`60000..60063`) are new. The
   ammfast side is the exact value that was rounded into the bank.
5. **write**: banks and `validation.json`. A bank is written only when all its rows exist and the
   gate and all spot checks pass; otherwise `complete` is `false` and `coverage` says exactly what
   exists.

### Checkpoints

State is under `scratch/replica-kit/<binding>/` (`cpython.jsonl`, `bank.jsonl`, `bench.json`,
`gate.json`, `log.jsonl`). `<binding>` is the SHA256 of the ammfast source digests, the reference
inventory digests (`reference/sources.json` and the five envelopes ammfast executes) and the
runtime versions (Python build, numpy, numba, llvmlite, platform, machine). Changing any of them
selects a new empty directory, and every checkpoint row carries the full digest: a row with
another digest, a duplicate, a malformed or non-finite row stops the run with `StaleState`. A
half-written last line from a kill is dropped. `generate.py` and `validate.py` themselves are
bound in `validation.json`, not in the checkpoint key, so `--stage all` after editing only them
rewrites the outputs from the existing rows.

## validation.json

`_credit` first, then among others:

- `complete`: boolean, true only with a passed gate, 576 passed spot checks and nine written banks.
- `bindings`: `{repository-relative path: sha256}` for `ammfast/*.py`, `generate.py`,
  `validate.py`, `reference/sources.json`, the reference envelopes used (including the archived
  kernel) and the nine banks. It does not contain its own hash, and banks refer to it by path
  only, so there is no hash cycle.
- `gates384`, `spots576`: arrays of `{policy, seed, cpython_edge, ammfast_edge, abs_error}` with
  unrounded values.
- `timings`: `{runs_per_second_per_core: {policy: number}, cold_jit_seconds: number}`; rates are
  one worker, warm, end to end through `run_batch`; `timing_notes` defines both.
- `coverage`, `benchmark`, `stage_wall_seconds`, `runtime`, `checkpoint_binding`, `limitations`.

## Result of the recorded run

- Gate 384/384 and spot 576/576 within `1e-9`; maximum absolute error `1.19e-11` (COMBO, seed
  64026); 519 of the 576 distinct pairs are bit-identical.
- 12288 of 12288 rows generated and written; `complete: true`.
- Pool wall time on 4 workers: 33 s gate CPython, 53 s banks, 19 s spot CPython; benchmark about
  60 s; the whole command 2 min 52 s.
- Cross-check, through `score.py` on bank rows, against the figures published in the COMBO
  reference README: report window `10000..12047` COMBO − qt1-ref `+0.597391 ± 0.013388`,
  TwoComp − qt1-ref `+0.424803 ± 0.012202`, COMBO − TwoComp `+0.172588 ± 0.010763`, mean edges
  `533.860222 / 533.687634 / 533.262831`; choose window `60000..61023` COMBO − TwoComp
  `+0.192478 ± 0.014753`. All reproduce (tested in `tests/test_replica_banks.py`).

## Limits

- Generated and checked on Linux x86_64 only; macOS arm64 is untested.
- The spot check covers the first 64 seeds of each bank, not every row. `validate.py --recompute N`
  re-derives more rows with ammfast, which checks the files, not ammfast against CPython.
- Scoring a policy against its own bank shows differences up to `5e-7` from the six-decimal
  rounding. `score.py`'s early stop can call such a zero-difference candidate "worse" when the
  rounding noise happens to average below zero; compare against a different policy's bank or read
  `mean_diff` itself.
- Banks are tied to the runtime versions in their provenance. On another platform, re-run the
  generator; the gate decides whether that platform reproduces CPython.
